# 多账号、上传治理与数据备份

## 多账号边界

QuePic 将以下数据按本地账号名称隔离：

- 语雀登录 Cookie；
- OpenAPI Token；
- 远程图片 URL 与上传记录；
- 图片分类；
- 滚动一小时上传额度。

切换账号后，上传页、文件夹转文档、图片库、缓存统计和额度状态都会跟随当前账号。账号名称只用于 QuePic 本地分组，不要求与语雀昵称一致。

## 图片去重与共享缓存

SHA-256 去重只在同一账号内生效：

- 同一账号重复提交同一图片时，直接复用该账号已有的远程 URL，不消耗上传额度；
- 不同账号提交相同图片时，仍分别上传到各自语雀账号，避免跨账号错误复用 URL；
- 相同内容在本地可以共享同一份预览和缩略图缓存；
- 删除一个账号下的图片记录时，只有在没有其他记录继续引用该 SHA-256 后，才删除物理缓存文件；
- 缓存空间统计按物理内容去重，避免同一份缓存被重复计入。

应用启动时会自动把旧版 `sha256 UNIQUE` 数据库约束迁移为 `UNIQUE(account_name, sha256)`，已有记录、分类和缓存索引保持不变。

## 上传额度

QuePic 对每个本地账号使用滚动一小时窗口：

- 保守上限：140 次远程上传尝试/小时；
- 最小间隔：25 秒；
- 失败的远程请求也计入本地额度；
- 同账号 SHA-256 去重在远程请求前执行，不消耗额度；
- 后端上传闸门会在锁内再次检查去重，并持续到本地索引写入完成，防止多个入口并发造成重复上传。

该限制用于在语雀约 150 张/小时的经验阈值下保留余量，不代表语雀官方承诺的固定配额。

## 缓存恢复顺序

清理本地缓存后，进入可视区域的图片按以下顺序恢复：

1. 检查本地缓存；
2. 对已保存的远程 URL 发起受控缩略图请求；
3. 使用图片所属账号的语雀会话回源；
4. 在用户显式开启时使用 WordPress CDN 兼容兜底。

远程 URL 请求只允许 HTTPS 的 `yuque.com` 和 `nlark.com` 域名，禁止重定向，最多两路并发，并保持全局请求间隔。

## 分类

图片分类存储于本地 SQLite 的独立关联表中。历史图片默认显示为“未分类”；普通上传可以指定分类；文件夹转文档上传的图片自动使用文件夹名称作为分类。

## OpenAPI Token

Token 按 QuePic 账号保存到操作系统密钥库，不写入 localStorage、SQLite、日志或前端配置。文件夹转文档创建文档时由 Rust 后端读取。

## 备份与恢复

QuePic 使用带版本清单的 `.quepic-backup` 压缩包，支持三种导出范围：

1. 仅设置：账号名称、当前账号、知识库 ID、默认分类和界面选项；
2. 设置与图片索引：增加 SQLite 图片记录、分类和上传额度；
3. 完整备份：同时加入本地预览与缩略图缓存。

导入时可以分别选择：

- 只恢复设置；
- 恢复设置与图片索引，并按需重新获取缩略图；
- 完整恢复图片索引与缓存。

完整恢复会检查备份格式版本、ZIP 路径、条目数量、解压体积以及 SQLite 完整性。缓存恢复后会根据当前设备目录重新建立绝对路径索引。

## 凭据安全边界

备份文件永远不包含：

- 语雀 Cookie；
- OpenAPI Token。

迁移到新设备后，需要为各账号重新登录语雀并重新保存 Token。
